# 家庭健康档案 · 微信小程序（云端版）开发文档

> 面向开发者的工程手册：框架、技术栈、目录结构、部署方式与其他开发信息。
> 产品定位与合规红线见 `README.md`。

---

## 1. 架构总览

本子项目是「家庭健康档案」的云端版，分三层，全部位于 `apps/miniprogram-app/`：

```
微信开发者工具 ──编译──> 前端(miniprogram/)  ── wx.cloud.callFunction ──> 云函数(cloudfunctions/api/)
                                                                        │
                                                               云数据库(23 集合) + 云存储
```

- **前端**：原生微信小程序（`WXML/WXSS/JS`），无第三方 UI 框架。
- **后端**：微信云开发，**单云函数 `api`** 多 action 分发（不是每个接口一个云函数）。
- **工具链**：Node.js 脚本，负责部署、建库、常量/纯函数同步、工程自检。

设计原则：**与微信环境接触的唯一文件是 `cloudfunctions/api/index.js`**。初始化 SDK、取 openid 都在那里；其余逻辑在 `lib/` 与 `actions/`，可在 Node 里直接加载测试（这也是为什么测试时代码能脱离微信环境跑）。

## 2. 技术栈

| 类别 | 选型 |
|---|---|
| 前端框架 | 微信小程序原生（`libVersion 3.5.5`） |
| 路由 | `app.json` `pages` + `tabBar`（声明式，无路由库） |
| 状态 | 页面内 `data` + `setData`，无全局状态库 |
| 网络 | `wx.cloud.callFunction`（前端）/ `wx-server-sdk`（云函数） |
| 后端运行时 | 微信云开发 Node.js |
| 数据库 | 云数据库（文档型，兼容 MongoDB 风格查询） |
| 存储 | 云存储（附件，仅临时链接） |
| 部署工具 | `miniprogram-ci` + `@cloudbase/manager-node` |

## 4. 前端要点

### 4.1 字段驱动表单
页面用 `FORMS` 对象描述表单结构（`fields` 含 `k/label/type/options/placeholder/hint/required`），配合 `FormSheet` 组件渲染。类型：`text / textarea / number / date / chips / multi`。改表单只需改 `FORMS`，无需动组件。

### 4.2 调用后端
```js
const res = await api.call('record.create', { ...payload });
// 返回 { code, data, message }，code === 0 表示成功
```

### 4.3 时间线合并
前端 `mergeTimeline` 把 5 张表（condition / medical_record / exam_report / vaccine / vital_sign）在**内存**中合并排序，不建索引表。映射关系：`KIND_TABS / TABLE2TYPE / KIND_SHORT`。

### 4.4 双视图
- **自查视图**（详细，主体）：全量记录。
- **医生视图**（派生）：从详细数据中提炼，附结构化摘要。

## 5. 纯函数层 `utils/`（核心约定）

| 文件 | 职责 |
|---|---|
| `constants.js` | **常量源**（CommonJS）。集合清单、权限等级、类型枚举、字段映射。**改这里，别改 shared。** |
| `model.js` | 数据模型：行 ↔ 业务对象转换（`fromVitalRow` / `summarizeVitals` / `mergeTimeline` / `buildSummary` 等） |
| `date.js` | 日期/时间格式化与解析 |
| `format.js` | 展示格式化（姓名遮蔽、单位等） |
| `validate.js` | 表单校验 |
| `api.js` | `wx.cloud.callFunction` 封装 |
| `guide.js` | 版本选择引导 |
| `page.js` | 页面通用方法混入 |

`check-project.js` 会 `require` 这些纯函数模块，确保它们没有误用 `wx` API（否则在 Node 测试环境会崩）。

## 6. 云函数后端要点

### 6.1 入口与分发
`cloudfunctions/api/index.js`：
1. `cloud.init({ env: cloud.DYNAMIC_CURRENT_ENV })`。
2. `createApp({ db, now })` 注入依赖。
3. `exports.main` 取 `OPENID`，调用 `app.handle(event, { openid })`。
4. 统一包 `_meta`（openid 前 6 位脱敏、env、ts）。

### 6.2 路由表 `actions/index.js`
用 `reg(name, route)` 注册。每个 route：
```js
reg('record.create', {
  auth: true,                 // 是否需要登录（默认 true）
  load: true,                 // 是否装配 用户/家庭 上下文（默认 true）
  handler: async (ctx, payload) => ({ ... })   // 返回 data
});
```
前端调用名即 `'命名空间.动作'`（如 `record.create`、`family.grantAccess`、`person.accessList`）。

### 6.3 `lib/` 内核
- `app.js`：`createApp` 装配上下文（ctx.openid、ctx.family、ctx.person 等），按路由分发。
- `auth.js`：鉴权（token/openid 解析，token 优先于 openid）。
- `audit.js`：审计。
- `crypto.js`：AES-GCM 敏感字段加密（手机号、身份证）。
- `errors.js`：统一错误码。
- `query.js`：云数据库查询封装（分页、操作符）。
- `pwd.js`：PBKDF2 密码哈希（纯 JS，与安卓同一份）。
- `shared/`：由 `miniprogram/utils` 生成，**勿手改**。

## 7. 数据模型（关键约定）

- **一期集合数 = 23**：含 `vital_sign` 体征指标。预留 `exam_item` / `exam_item_dict`（二期）、`share_link`（后期）。
- **时间双字段**：`occurred_at`（实际发生）与 `recorded_at`（补录时间）必须分开保存，避免时间线乱序。
- **长期用药 ≠ 本次用药**：`long_term_medicine`（`time_slots`）是长期方案；某次用药记录在 `timeline_event.content`。绝不混表。
- **权限判定走 `person_access`**，不看 `role`（admin 只管成员进出家庭）。
- **每张业务表带 `family_id`**，且**只信服务端反查结果，不信前端传参**。
- **敏感字段加密**：`user.phone`、`person.id_card`、`emergency_contact.phone`（见 `crypto.js`）。
- 集合与索引的权威定义见 `scripts/deploy/schema.js`（建库脚本读它）。

## 8. 代码同步机制（三端对齐，避免分叉）

同一份业务逻辑派生出安卓版。同步关系：

| 源（手写） | 派生（生成） | 脚本 |
|---|---|---|
| `miniprogram/utils/{constants,date,format,model,validate}.js` | `cloudfunctions/api/lib/shared/*.js` | `npm run sync`（`sync-shared.js`） |
| `cloudfunctions/api/actions/*` + `lib/*` | `android-app/src/server/*` | `android-app npm run gen:server`（`convert-server.js`） |
| `miniprogram/**/*.wxss` | `android-app/src/styles/*` | `android-app node scripts/convert-styles.js` |

> ⚠️ 改完云端小程序逻辑后，**务必先 `npm run sync`**，否则云函数端的共享模块会落后于前端源。曾发生摘要逻辑落后导致把已愈慢性病误带进医生摘要的 bug。

## 9. 部署

### 9.1 凭据 `deploy.config.json`
字段：`appid` / `envId` / `secretId` / `secretKey` / `encKey` / `privateKeyPath`。**已在 `.gitignore`，切勿提交**。
- `encKey` 一旦投产**不可更换**。

### 9.2 流程
```bash
npm install
npm run deploy:setup        # 向导填写凭据
npm run deploy:check        # 校验工具链与凭据（零改动）
npm run deploy -- --dry-run # 预演（零改动）
npm run deploy              # 一键：建库 + 上传小程序包 + 传云函数
# 分步：
npm run deploy:db           # 仅建库/建索引
npm run deploy:fn           # 仅传云函数
npm run deploy:upload       # 仅传小程序前端包
```
`upload.js` 用 `miniprogram-ci` 上传，`ignores` 已排除 `node_modules/`、`cloudfunctions/`、`scripts/`、`demo/`、`*.md` 等。

### 9.3 上线分两段
- **A 段（家人自用）**：注册 + 认证 + 部署 + **发体验版**（执照 3~5 天 + 认证 1~3 天）。
- **B 段（公开搜到）**：ICP 备案 + 提审 + 发布（7~20 工作日）。A 段完成即可家人自用，B 段不阻塞。

## 10. 开发工作流（典型改动）

1. 改前端页面 / 常量 / 模型 → 在 `miniprogram/` 与 `miniprogram/utils/`。
2. 改后端 action → 在 `cloudfunctions/api/actions/` 注册于 `actions/index.js`。
3. 跑 `npm run sync` 同步 shared。
4. 跑 `npm run check` 自检结构。
5. 微信开发者工具编译预览。
6. 部署：`npm run deploy:check` → `npm run deploy`。
7. 若安卓也要跟上：`android-app` 跑 `npm run gen:server` + `node scripts/convert-styles.js`。

## 11. 工程自检 `check-project.js`

校验：① `project.config.json` 可解析；② `app.json` 可解析；③ 每个页面四件套（.js/.wxml/.json/.wxss）齐全；④ tabBar 数量 2~5 且 pagePath 在 pages 内；⑤ 页面 json 可解析；⑥ `utils` 纯函数可 Node 加载（防误用 wx）；⑦ 云函数入口与 package.json 齐备；⑧ sitemap 文件存在。

---

## 12. 合规红线（不可越过）

- **去医疗化**：文案不出现「诊断 / 处方 / 建议服用」。
- **零推送**：提醒仅站内展示，不接订阅消息。
- **无 AI 诊断**：报告解读为人工标注，不生成自动诊断结论。
- **隐私**：手机号/身份证加密；附件私有，只发临时链接，不产生公开图片 URL；不接医院 HIS。
- **个保法**：档案共享须归属人本人授权（敏感信息单独同意）。

## 13. 常见坑

- `app.json` 页面四件套缺一个，`check-project` 会报「页面文件缺失」。
- 改了 `utils/constants.js` 但忘了 `npm run sync` → 云函数端常量过期。
- `deploy.config.json` 被提交到仓库 → 泄露密钥（已在 .gitignore，注意别手动 `git add`）。
- 前端误用 `wx.*` 在 `utils/` 纯函数里 → Node 环境加载失败。
