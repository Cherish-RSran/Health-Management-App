## 一、项目定位与交付形态

**一句话定位**：带家人看病时，30 秒把事情说清楚的东西。入口是子女代录（自查详细），产出是给医生看（提炼摘要）。不是健康档案管理系统。

| 终端 | 目录 | 数据 | 状态 |
|---|---|---|---|
| 微信小程序（云端版） | `apps/miniprogram-app/` | 微信云开发（云数据库 + 云存储 + 云函数） | 工程完成；待账号凭据部署 |
| 安卓本机版 | `apps/android-app/` | IndexedDB，全存本机、不联网 | Web 构建通过；APK 曾产出，未真机验证 |
| 交互原型 | `demo/index.html` | 静态内存数据 | 单文件，供设计评审 |

## 二、当前产品设计

### 2.1 双视图

| | 自查视图（主体） | 医生视图（派生） |
|---|---|---|
| 谁看 | 用户与家人 | 医生，只看几十秒 |
| 内容 | 全量、详细、不删 | 提炼、精简、只留必要 |
| 目的 | 回溯身体情况、翻出「上次也这样过」 | 30 秒掌握底子 + 这次怎么了 |

**设计结论**：录入时保持完整，展示时才筛选。详细数据有长期价值；医生摘要每次可重新生成。

**摘要构成**：

- 自动必带（不可取消）：过敏史、基础病、长期用药、年龄 / 性别 / 血型。
- 本次病程：时间线压缩成 3~5 条关键节点 + 本次用药汇总。
- 可勾选：相关历史病程、检查报告、手术史；默认按相关性预选，记住上次选择。
- 过敏史永远排第一。输出 / 复制 / 保存为图片均已实现。报告要点为**人工标注**，不生成 AI 诊断。

### 2.2 补记模式

子女下班后补记，不是生病时随手记。三步：选症状与历史开始日期 → 逐日分组填写（可加天、可留空）→ 选择仍在继续 / 已结束。补记第 1 步有明确引导卡；首页入口文案为「补记病程」。

`timeline_event` 同时保存：

- `occurred_at`：实际发生时间，用于时间线排序与统计。
- `recorded_at`：补录时间，用于审计与溯源。

### 2.3 健康时间线

生病 / 就诊 / 检查 / 体检 / 疫苗 / 体征六类混排。必须配三件事：类型徽标、顶部筛选、进行中置顶（其余按时间倒序、按月分组）。一期由云函数并行查多表 + 内存合并，不建索引表。

### 2.4 首页与提醒

- 「今天要吃的药」按人 × 早 / 中 / 晚分组，带当前时段高亮与本地临时「已服」提示（不写云端、不打卡）。
- 今日待办：复查 / 疫苗 / 逾期，站内高亮。
- 用药余量 `remaining` 与续方 / 复诊日 `refill_at`，仅站内提示。
- **一期零推送**：不接订阅消息、不建额度池。
- 大字模式开关前置；卡片长按拖动排序并持久化。

### 2.5 权限

权限判定走 `person_access`，`level = owner / edit / read / none`。`role=admin` 只管成员进出，**不代表能看全部档案**。代管档案必须记录「已获本人同意」。跨家庭访问统一按「不存在」返回，不泄露数据存在性。

## 三、技术架构

### 3.1 技术栈

| 层 | 选型 |
|---|---|
| 小程序前端 | 原生 WXML / WXSS / JS，基础库 3.5.5，不用 uni-app |
| 云端后端 | 微信云开发：单个 `api` 云函数（Node.js）+ 云数据库 + 云存储 |
| 安卓端 | Capacitor 7 + Vue 3 + Vite 6 + IndexedDB |
| 加密 | AES-256-GCM（敏感字段）+ PBKDF2（密码 / 手机号检索摘要，纯 JS 两端同份） |
| 部署 | miniprogram-ci + @cloudbase/manager-node 脚本化 |

### 3.2 云函数分层

```
cloudfunctions/api/
├── index.js              # 唯一接触 wx-server-sdk 的薄壳
├── lib/
│   ├── app.js            # createApp({db, openid, now}) → handle(event)
│   ├── auth.js           # 登录态、家庭反查、权限
│   ├── audit.js          # 审计日志
│   ├── crypto.js         # 加解密
│   ├── errors.js         # 统一错误码，永不抛原始异常
│   ├── pwd.js            # 纯 JS PBKDF2
│   ├── query.js          # fetchAll 分页拉全
│   └── shared/           # 由小程序 utils 同步生成的纯函数副本
└── actions/              # 10 个业务模块，全部在 index.js 注册
```

所有集合设「仅管理端可读写」，前端不直连数据库。每张业务表带 `family_id`，但只信服务端从登录态反查的结果。

### 3.3 三端同步规则

1. `miniprogram/utils/*.js` 是源；`cloudfunctions/api/lib/shared/` 由 `node scripts/sync-shared.js` 生成，勿手改。
2. 安卓 `src/core/constants.js` 是手工 ESM 镜像；`src/core/model.js` 与 `src/server/actions/*` 由 `npm run gen:server` 从云端生成。
3. 安卓 `src/styles/*` 由 `node scripts/convert-styles.js` 从 wxss 生成（rpx → calc、page → :root）。
4. 改完云端必须重跑同步，否则会出现「云函数摘要逻辑落后于小程序源」这类分叉。

### 3.4 账号体系

- openid 账号与手机号账号并行：小程序 `auth.login` 自动建号、`auth.bindCredential` 补密码；安卓 `auth.register` 建号。
- token 在内核层换成 user_id，**优先于 openid**；业务 action 仍只认 `ctx.openid`，一行未改。
- `user_credential` 存 `phone_enc`（AES-GCM，展示 / 备份）与 `phone_hash`（PBKDF2 固定盐，供 `where` 检索）。带随机 IV 的密文不能用于查询。
- 手填手机号未做短信验证，`phone_verified_at` 恒空。

## 四、数据模型（当前 23 集合）

> 唯一事实来源：小程序 `utils/constants.js` 的 `ONE_PHASE_COLLECTIONS`。

### 4.1 全局约定

- 每张业务表带 `family_id`；服务端反查，不信前端传参。
- 所有集合「仅管理端可读写」，前端一律走云函数。
- 主键 `_id`；时间存毫秒时间戳；只到天的日期存 `YYYY-MM-DD`；软删除用 `status`。
- 所有表带 `created_at` / `created_by`，可变表带 `updated_at`。
- 🔒 加密字段：`user.phone`、`person.id_card`、`emergency_contact.phone`。

### 4.2 集合清单

| 分组 | 集合 |
|---|---|
| 账号与家庭 | `user`、`family`、`user_family` |
| 档案与权限 | `person`、`person_access` |
| 常备档案 | `allergy`、`chronic_disease`、`surgery`、`long_term_medicine`、`emergency_contact` |
| 病程核心 | `condition`、`timeline_event`、`symptom_dict` |
| 医疗记录 | `medical_record`、`exam_report`、`vaccine`、`vital_sign` |
| 提醒 | `todo` |
| 系统 | `file`、`audit_log`、`user_setting` |

预留：`exam_item`、`exam_item_dict`（二期），`share_link`（后期，一期不建）。

### 4.3 关键字段

- `user`：`_id = openid`；`phone` 加密；`has_password` 仅展示用。
- `user_credential`：`phone_enc` / `phone_hash` / `password`（`pbkdf2$轮数$salt$hash`）。
- `user_session`：`_id` 即 token；`expires_at` 默认 180 天。
- `family`：`invite_code`（6 位，唯一 + 7 天有效）、`owner_user_id`（唯一）。
- `person`：`profile_type = self|managed`；`owner_user_id` / `custodian_user_id` / `consent_note`；`status = active|archived`。
- `person_access`：`level = owner|edit|read|none`；`source = self|delegated|family_default`。
- `allergy`：`allergen` / `allergen_type` / `severity` / `reaction`；就诊卡永远放最前。
- `chronic_disease`：`status = active|cured`；已愈不进医生摘要的「基础病（长期）」。
- `long_term_medicine`：`time_slots`（morning / noon / evening / bedtime）、`start_date` / `end_date`（空 = 长期）、`for_disease`（存病名而非 ID）、`remaining` / `refill_at`。**不存本次吃药**，本次用药在 `timeline_event.content`。
- `condition`：`start_date`、`end_date`、`status = ongoing|ended`、`max_severity`。
- `timeline_event`：`event_type = symptom|medication|visit|exam|note`；`occurred_at` 与 `recorded_at` 分离；`file_ids`。
- `vital_sign`：`metric_type = blood_pressure|blood_glucose|weight|temperature|other`；`value` 字符串（血压如 `120/80`）；`vital_date` / `vital_date_ts`；参考区间仅展示，**不构成医疗建议**。
- `medical_record`：`diagnosis` 只记录医生原话，系统不自动生成诊断。
- `exam_report`：`report_type = lab|imaging|checkup|other`，决定时间线显示「检查」还是「体检」；`summary_note` 为人工标注要点。
- `vaccine`：`next_date` 自动生成待办。
- `todo`：`type = recheck|vaccine|exam|custom`；`remind_ahead_days` 仅用于站内高亮。
- `file`：云存储私有，只发临时链接，**绝不产生公开 URL**。
- `audit_log`：所有写操作 + 摘要查看都记，审计失败不影响主流程。

### 4.4 索引（建库时一次建好）

`family.invite_code` 唯一、`family.owner_user_id` 唯一；`user_family(user_id, family_id)` 唯一、`(family_id, join_status)`；`person(family_id, status)`；`person_access(person_id, user_id)` 唯一；`condition(person_id, status, start_date desc)`、`(family_id, start_date desc)`；`timeline_event(condition_id, occurred_at)`、`(person_id, occurred_at desc)`、`(family_id, occurred_at desc)`；`medical_record / exam_report / vaccine` 按 person + date；`todo(family_id, status, due_date)`；`audit_log(family_id/created_at)` 与 `(person_id, created_at)`；常备档案与 `file` 按 `person_id`。

唯一索引不是可选项：并发加入家庭 / 建家庭的幂等依赖它，缺失会静默产生重复记录。

### 关键坑与修复（41 条缺陷中影响最大的）

| 缺陷 | 后果 | 修复 |
|---|---|---|
| `app.js` 调用 `login`，服务端注册的是 `auth.login` | 启动即登录失败，整体不可用 | 改对 action 名 + 静态断言「前端调用的 action 必须已注册」 |
| `person.update` / `archive.update` 用含 required 的完整规则校验 | 所有编辑必然失败 | 抽出 `optionalRules()` |
| `loadContext` 以 user 记录存在为前提 | 未 login 时家庭功能全挂 | 家庭归属只依据 `user_family` |
| 新增待办提交到 `record.add` | 整条链路失败 | 按表单声明的 `api` 路由到 `todo.add` |
| 紧急联系人回填脱敏号 | 创建后无法编辑 | 回填 `phone_full` |
| 归属人可把自己设为 `none`，枚举无 `owner` | 不可逆自我锁死 | 禁止改自己 + 补 `owner` |
| 归档档案仍通过 `owner_user_id` 兜底获 owner | 归档等于没归档 | 兜底限定 `status=active` |
| `export.data` / `condition.detail` 固定 `limit(100)` | 「全量导出」不全 | 新增 `lib/query.fetchAll` 循环分页 |
| `family.owner_user_id` 唯一索引只在测试里 | 并发建家庭产生重复 | 补进建库 schema 与部署校验 |
| 首页 N+1 查询 | 8 成员 = 8 次串行往返 | 改批量 `in` 查询 + 内存分组 |
| `--dry-run` 仍写 appid 进工程配置 | 预演污染版本库 | dry-run 零改动 + 守卫断言 |
| 测试直接写真工程配置 | 测试全绿、工程已脏 | 临时目录沙箱 + 路径注入 |
| 只认 `--set=k=v`，非 TTY 仍进问答 | 进程卡死 / CI 超时 | 两种写法都支持 + `isTTY` 判断 |

其余修复涵盖：空数组绕过校验、并发加入重复成员、年龄用系统时钟、`todo.list` 未排除 skipped、跨家庭泄露存在性、未知性别显示错误、非管理员显示管理员标签、日期选择器无法清空、表单观察器覆盖输入、重复 hide loading、页面并发重复请求等。

**新增跨文件静态断言**：`navigateTo` 参数必须在目标页 `onLoad` 读取；表单声明的提交接口必须已注册；紧急联系人回填必须 `phone_full`；前端调用的所有 action 必须已注册；跑完校验工程配置仍干净；dry-run 后配置不变；`--set` 两种写法等价。

**独立对抗性审查**：只看代码不看测试，命中 3 严重 / 9 中等 / 10 轻微，全部修复。核心收获：业务逻辑测试与前端接线正确性是两件事，300 用例全绿也测不出「点了没反应」。

## 六、部署与上线

### 6.1 一键部署

```bash
cd apps/miniprogram-app
npm install
npm run deploy:setup     # 交互式填凭据，逐项校验；非 TTY 用 --set k=v
npm run deploy:check     # 体检
npm run deploy -- --dry-run
npm run deploy           # 建库 → 部署云函数 → 上传代码
```

分步：`deploy:db`、`deploy:fn`、`deploy:upload`；只看配置：`deploy:show`（敏感值脱敏）。

配置字段：`appid`、`privateKeyPath`、`envId`、`secretId`、`secretKey`、`encKey`。可用环境变量注入：`FHR_APPID`、`FHR_ENV_ID`、`TENCENT_SECRET_ID`、`TENCENT_SECRET_KEY`、`FHR_UPLOAD_KEY_PATH`、`FHR_ENC_KEY`。配置文件已在 `.gitignore`，**分享时必须保持为空**。

`encKey` 若已用于生产绝不可更换；换密钥 = 已加密的手机号 / 身份证永久解不开。

### 6.2 手工路径

1. 微信开发者工具导入 `apps/miniprogram-app/`（该层有 `project.config.json`），确认 `miniprogramRoot = miniprogram/`、`cloudfunctionRoot = cloudfunctions/`。
2. 云开发控制台建 23 个集合，权限全部「仅管理端可读写」，按 §4.4 建索引。
3. 右键 `cloudfunctions/api` → 上传并部署：云端安装依赖。
4. 云函数配置加环境变量 `FHR_ENC_KEY`（32 字节随机 hex），内存 256MB / 超时 20s。
5. 云函数测试事件 `{ "action": "ping" }` 应返回 `pong: true`。

### 6.3 上线路径

- **A 段（家人自用）**：办个体工商户执照（经营范围写健康咨询非诊疗 / 信息技术 / 软件开发 / 数据处理，**禁写医疗、诊疗、药品、问诊**）→ 注册小程序（主体选「企业」大类，个体户无单独选项）→ 微信认证 → 开云开发 → 拿密钥 → 部署 → 发体验版。执照 3~5 天 + 认证 1~3 天。**A 段完成即够家人用**。
- **B 段（公开可搜）**：小程序 ICP 备案（免费，7~20 工作日）→ 提审 → 发布。12381 短信核验须 24 小时内完成。
- 不配服务器域名，所以**不需要域名备案**；小程序 ICP 备案仍必须。
- 一期代码未用 `getPhoneNumber`，个人主体下也能完整运行，可作当天验证的加速路径；代价是换主体 = 换环境 = 测试数据不迁移。
- `app.json` 未开 `__usePrivacyCheck__`；因用头像昵称填写能力、不涉及隐私接口，可免弹窗，但提审前仍须在公众平台配《用户隐私保护指引》。

### 6.4 人工验收清单（重点）

编译无报错；建家庭 / 邀请码 / 审批 / 授权链路通；代管须勾同意；过敏 / 基础病 / 手术 / 用药 / 紧急联系人 CRUD 通；长期与短期用药区分正确；补记逐日、空日显示「—」、进行中置顶；时间线六类混排 + 筛选；医生摘要过敏史第一、短期药不混入长期、可复制 / 保存；数据导出不含明文手机号；页面有去医疗化声明；iOS / Android 真机与安全区正常；弱网与断网有兜底。

## 九、合规红线

- 零推送：提醒仅站内展示，不接订阅消息。
- 无 AI：报告要点为人工标注；不生成诊断 / 用药建议 / 药物冲突结论。
- 去医疗化：文案不出现「问诊 / 诊断 / 处方 / 建议服用」；`diagnosis` 字段只记录医生原话。
- 数据共享须归属人本人授权；附件私有只发临时链接；不接医院 HIS。
- 敏感字段加密；跨家庭按「不存在」返回；审计留痕。
- `encKey` 一旦投产不可更换；部署配置不得提交或随项目分享。
