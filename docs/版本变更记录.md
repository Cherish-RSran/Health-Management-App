## 二、需求与产品版本

### v1 · 需求原稿（已被取代）

提出健康档案、AI 多维分析、药物冲突分析、提醒中心等构想。问题：类目偏医疗、手机号当主键、头像昵称获取方式失效、权限未独立建模、AI 结论有合规风险。

### v2 · 评审优化（已被 v3/v4 取代）

- 类目改为「工具 - 健康管理」。
- 主键改为 `openid`，手机号降为可换绑的加密字段。
- 新增 `person_access` 表；共享档案须归属人本人同意。
- 长期订阅能力取决于**服务类目**而非主体身份；「工具 - 健康管理」拿不到长期订阅。
- 主体定个体工商户（注册时归在「企业」大类；主体不可变更）；经营范围禁写医疗 / 诊疗 / 药品 / 问诊。
- 提醒改为站内待办为主；技术选型定为微信云开发。

### v3 · 四目标重构（已被 v4 取代）

- 定位：**带家人看病时，30 秒把事情说清楚的东西**。
- 数据分两类：常备档案（低频 / 长期）与病程记录（高频 / 短期）。
- 长期用药 ≠ 本次用药，必须分表。
- 新增就诊卡、医生模式、病程单；AI 建议一期不做。

### v4 · 当前有效需求（已全部实现）

- **双视图**：自查 = 全量详细（主体）；医生 = 从中提炼（派生）。录入完整，展示时筛选。
- **补记模式**：子女下班后补，支持历史日期、逐日补录；`occurred_at` 与 `recorded_at` 分离。
- **一期零推送**：不接订阅消息、不建额度池；提醒仅站内。
- **健康时间线**：生病 / 就诊 / 检查 / 体检 / 疫苗 / 体征混排，带类型徽标、筛选、进行中置顶。
- 二维码分享后期做，只留结构。
- 医生摘要：自动必带（过敏 / 基础病 / 长期用药 / 年龄血型）+ 本次病程压缩 + 可勾选历史；过敏史永远第一。

## 三、开发阶段

| 阶段 | 内容 | 结果 |
|---|---|---|
| P0 | 工程骨架、设计 token、5 个纯函数模块、数据库内核、页面骨架 | 78 用例 |
| P1 | 云函数内核：action 路由、登录态、家庭反查、权限、审计、统一错误码 | +32 |
| P2 | 账号 / 家庭 / 邀请码 / 加入 / 审批 / 成员 / 移交 / 授权 | +34 |
| P3 | 档案 CRUD、五张常备档案表、AES-256-GCM 加密、长短期用药 | +32 |
| P4–P8 | 病程时间线、医生摘要、首页待办、页面 UI、端到端旅程、稳定性 | 累计 300 用例通过 |
| P9 | 部署工具链：建库 / 索引 / 云函数 / 上传 / CLI 编排 | +32 |
| P10 | 部署配置向导；CLI 兼容 `--set k=v` 与 `--set=k=v`；非 TTY 保护 | 累计 357 用例通过 |

### 架构变更

- 云函数拆两层：`index.js` 唯一接触 `wx-server-sdk`；业务内核接收注入的 `{db, openid, now}`。
- 单一 `api` 云函数 + action 路由，公共代码不复制。
- `miniprogram/utils/*.js` → `cloudfunctions/api/lib/shared/` 由 `sync-shared.js` 同步。
- 所有集合仅管理端可读写；`family_id` 服务端反查；跨家庭统一按「不存在」返回。
- 2026-11-05 按用户指令删除全部测试代码。静态校验与构建保留。
